6. Key decisions

Keep the original grey-background PNGs.The source files are the durable authoring record. Fake transparency is not requested from the image model; removal is deterministic and reviewable in code.
Embed raster tiles inside the SVG sprite contract.This preserves cm-chessboard's required group IDs and drag behavior without converting detailed sculpted artwork into lossy hand-traced paths.
Retain vector alternatives.faceted.svg and silhouette.svg remain available as project-authored fallbacks; Design-1 is only the active selection.
Keep all QA local.No GitHub Actions test workflow is introduced. Unit, build and browser gates run through the existing local npm commands.

7. Risks and mitigations

Raster sprite weight: the generated sprite is approximately 533 KB. Mitigation: each tile is downsampled to 256 x 256, build size limits remain active, and the sprite is fetched once.
AI-assisted artwork provenance: legal treatment of AI-assisted output can vary by jurisdiction. Mitigation: documentation states only supported facts: owner direction, owner provision, selected tool and no intentionally supplied third-party chess asset. The record explicitly avoids giving a legal opinion.
Source background assumptions: the fitter is tuned to the selected neutral studio renders. Mitigation: exact dimensions and filename contracts are tested; materially different future source styles should receive a new generator profile rather than weakening current thresholds.
Mobile board area: the evaluation bar and bordered shell reduce the inner board to roughly 322px at 390px viewport width. Mitigation: visual QA confirms legibility and no overflow; the shell uses a reduced 6px mobile padding.
