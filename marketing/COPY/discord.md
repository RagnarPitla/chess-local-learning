# Discord copy

## What's actually verified vs. general practice

Discord servers set their own rules per-server, and those rules live inside the server (pinned
messages, a #rules channel, or a dedicated #self-promo / #showcase channel description) rather than
on the public web, so they cannot be fetched and quoted the way the r/chess wiki or the Lichess
forum etiquette page can. This file is honest about that: it names two real, well-known chess
communities with Discord servers worth trying, states what's independently confirmable about them,
and gives a generic-but-strict checklist to apply to any server before posting - because "ignored
the pinned self-promo rules" is exactly the kind of removal this task is trying to avoid.

- **Lichess's official Discord** exists and is linked from lichess.org; like most large servers it
  is understood to run a dedicated self-promotion/showcase-style channel rather than allowing
  project links in general chat, but the exact channel name and posting cadence rules were not
  independently verifiable from outside the server at research time - confirm by reading that
  channel's own pinned rules before posting anything.
- **ChessDojo's Discord** (the community around the ChessDojo Training Program) is a real,
  well-known chess-improvement community, which makes it a good topical fit for a training tool -
  again, confirm its current self-promo/showcase channel and rules directly in the server before
  posting, since this file cannot verify that server's pinned rules from outside it.

Do not treat either bullet above as a guarantee of what those servers currently allow - treat it as
"worth checking," and apply the checklist below once inside.

## Checklist before posting to any chess or dev Discord server

1. Read the server's #rules (or equivalent) and any pinned message in the specific channel you plan
   to post in - assume nothing carries over from a different server.
2. Post only in a channel explicitly designated for sharing your own projects (commonly named
   #self-promo, #showcase, #your-projects, #feedback, or similar) - never in general chat, general
   chess discussion, or a channel dedicated to something else, even if it seems related.
3. If no such channel exists, ask a moderator directly (or in a general "can I share X here"
   question) before posting, rather than assuming a general channel is fine.
4. Post once per server. Do not repeat the same post across many servers on the same day - space it
   out and adapt each post to the server's actual culture rather than copy-pasting identically.
5. Never DM other members with the link unsolicited, even if they seem like a good fit.
6. Stay and answer questions if anyone responds - a post-and-leave pattern reads as spam even in a
   channel built for sharing projects.

## Draft post (use inside an appropriate self-promo/showcase channel only, adapted per server)

I built a free, open-source chess trainer and wanted to share it here since it's directly relevant
to this server: https://ragnarpitla.github.io/chess-local-learning/

The idea: chess lessons teach you a script (if they play X, you play Y), and real opponents don't
follow scripts. This plays you at a chosen strength (Stockfish, running client-side), tags mistakes
with a real reason instead of just a centipawn number, builds drills from your own games, and
explains it when an opponent leaves known theory instead of going quiet.

No account, no upload, MIT licensed. Source: https://github.com/RagnarPitla/chess-local-learning

Would genuinely value feedback from people who actually play here, especially anything that feels
wrong or missing.
